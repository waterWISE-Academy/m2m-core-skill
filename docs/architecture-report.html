Architecture Review: M2M Protocol Depth

1. Event Listener Seam Leak (Shallow Interface)

Strong
Files: .github/workflows/m2m-protocol.yml

Problem: The reusable workflow strictly filtered events using github.event_name == 'issue_comment'. When invoked as an adapter (via workflow_call) from a Spoke repository, the event context changes, causing the engine to silently skip execution. This creates a brittle, shallow boundary where the Hub cannot reliably listen to its Spokes.

Solution: Deepen the interface by increasing its leverage. We broadened the filter to accept both issue_comment and issues, and inspected the payload dynamically to extract the user from either context.payload.comment or context.payload.issue.

Benefits: Higher locality. The Hub engine can now confidently accept triggers without forcing the Spoke to format its events in a rigid, single-use structure.

2. LLM Output Parser Fragility (Lack of Locality)

Strong
Files: .github/scripts/m2m_agent_router.js

Problem: The JSON parsing logic relied on string matching (startsWith('```json')) to strip markdown. This formed a shallow module that crashed easily if the LLM hallucinated conversational text around the block. This caused the system to frequently fall back to a mock file generation.

Solution: Replaced the manual string slicing with a robust Regular Expression seam (/```(?:json)?\s*([\s\S]*?)\s*```/) to extract the code block payload, with a secondary fallback array match. This isolates the parsing concern.

Benefits: Improved locality and resilience. The router can now safely ingest LLM outputs regardless of formatting wrappers.
